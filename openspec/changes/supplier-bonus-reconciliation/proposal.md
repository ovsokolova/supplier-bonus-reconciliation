# Предложение (Proposal): Автоматическая сверка взаиморасчётов и бонусов поставщиков (PoC)

## Проблема

Розничные сети («Эльдорадо») при расчёте бонусов с поставщиками
(денежными и товарными) вынуждены полагаться на ручную сверку.
Бонусные условия в приложениях к договорам, ступенчатые ретро-бонусы
в Excel и фактические данные о закупках и оплатах не проверяются
автоматически.

Следствия:

- недоначисленные или пропущенные бонусы;
- споры с поставщиками выявляются слишком поздно;
- сотрудники тратят время на PDF, Excel и 1С.

## Цель

Построить конвейер:

1. Извлекать бонусные условия из договоров и Excel-приложений
   через OCR + LLM.
2. Сопоставлять с фактическими данными ERP
   (объём закупок, сумма оплат, возвраты).
3. Подсвечивать расхождения.
4. Формировать отчёт о сверке.
5. Формировать черновик претензионного письма.

## Границы

**Входит**:

- извлечение условий из PDF, сканов, Excel;
- движок сопоставления на правилах;
- нормализация и нечёткое сопоставление наименований
  поставщиков и номенклатуры;
- классификация расхождений;
- интерфейс проверки на Streamlit;
- экспорт отчёта о расхождениях.

**Не входит**:

- интеграция с 1С/ERP в реальном времени
  (на PoC — замена выгрузкой CSV);
- отправка претензий с юридической силой;
- портал самообслуживания для поставщиков.

## Критерии успеха

1. Точность извлечения полей условий (база, ставка, период)
   из 20 образцов договоров — не менее 85 % (вручную).
2. Для 10 известных сценариев расхождений выявляемость 100 %,
   ложных — не более 15 %.
3. Время обработки одного договора
   (OCR → извлечение → сверка → отчёт) — не более 3 минут.
4. Доля ложных missing_in_actuals из-за различий в написании —
   не более 5 % после включения нечёткого сопоставления.
5. Весь LLM-инференс — локально (Ollama);
   внешние API — только по согласованию с ИБ.
