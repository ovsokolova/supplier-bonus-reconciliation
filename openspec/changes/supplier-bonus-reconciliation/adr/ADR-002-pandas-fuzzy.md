# ADR-002: pandas + rapidfuzz как движок сверки

**Статус**: принято

**Контекст**: необходимо сопоставлять условия договора
(по поставщику, товару, периоду) с фактическими данными ERP
(объём закупок, сумма оплат) и различать типы расхождений.
Наименования контрагентов и номенклатуры систематически
различаются между договором и ERP.

**Решение**: перед внешним соединением pandas выполняется
нормализация ключей, а при отсутствии точного совпадения —
нечёткое сопоставление через rapidfuzz с настраиваемым порогом.
Соединение выполняется по составному ключу
supplier + product + period с допуском по сумме.

**Обоснование**:

- системы сверки, подобные ReconX, подтвердили подход
  outer join pandas + правила классификации;
- правила допуска — стандарт для финансовых сверок;
- примеры вида «ООО Пример» vs «ООО Пример-Трейд» —
  типичная ситуация в рознице;
- rapidfuzz быстрее и точнее стандартного difflib,
  устойчив к перестановке слов;
- производительности pandas достаточно для PoC,
  БД избыточна.

**Последствия**:

- плюсы: простая реализация, прозрачные правила,
  меньше ложных missing_in_actuals;
- минусы: давление на память при больших объёмах;
  требуется калибровка порога;
- нейтрально: нормализация до сверки; строки matched_fuzzy
  отображаются с коэффициентом схожести.

**Альтернативы**:

- только точный ключ: много ложных missing_in_actuals;
- БД и SQL: избыточно для PoC.
