# ADR-004: Стратегия тестовых данных

**Статус**: принято

**Контекст**: для проверки критериев успеха (85 % точности
извлечения, 100 % выявляемости, ≤15 % ложных) нужны
размеченные образцы договоров и выгрузок ERP. Реальные
договоры содержат коммерческую тайну и не могут быть
закоммичены в репозиторий.

**Решение**: двухуровневая стратегия.

1. **Синтетические фикстуры** — генерируются программно,
   коммитятся в data/examples/ (исключение в .gitignore).
   Покрывают сценарии: денежный бонус, товарный бонус,
   ступенчатый, с НДС / без НДС, разные написания поставщиков,
   с ИНН и без.

2. **Реальные обезличенные данные** — хранятся вне
   репозитория (внутреннее хранилище), доступ через
   переменную окружения TEST_DATA_PATH. Не коммитятся.

**Обоснование**:

- синтетика позволяет воспроизводить тесты без ИБ-ограничений;
- реальные данные нужны для финальной калибровки, но их нельзя
  версионировать;
- разделение даёт воспроизводимость CI и валидацию на реальных
  данных.

**Последствия**:

- плюсы: CI работает на синтетике; реальные данные не утекают;
- минусы: нужно поддерживать генератор фикстур;
- нейтрально: TEST_DATA_PATH опционален.

**Альтернативы**:

- только реальные данные: невозможно в CI, риск утечки;
- только синтетика: не отражает реальные формулировки.
